# 작은 서버에서는 이미지를 밖에서 빌드한다

- 날짜: 2026-11-23

## 문제

서버를 4GB에서 1GB VM으로 줄였다. 4GB에서는 서버에서 이미지 빌드(Next.js)가 됐지만, 1GB에서는 메모리가 모자랄까 걱정됐다. 1GB에서 빌드를 시도해 보지는 않았다.

## 원인

이미지 빌드는 실행보다 메모리를 훨씬 많이 쓴다. 1GB에서 빌드하면 OOM이나 스왑 때문에 느려지고, 돌고 있는 앱과 DB까지 밀려날 수 있다. (추론)

## 해결

서버에서는 빌드하지 않기로 했다.

- 다른 곳에서 빌드해 옮긴다. (안 써 봄)
  ```bash
  docker build --target runner -t <이미지>:latest .
  docker save <이미지>:latest | gzip | ssh <서버> 'gunzip | docker load'
  ```
- 서버에서는 `docker compose ... up -d --no-build`로만 띄운다.

## 배운 점

- 실행만 할 때는 Postgres, 마이그레이션(한 번 돌고 끝남), Next.js 앱, Caddy 네 서비스로 메모리 사용이 약 420MB였다.
- 서비스에 `image:`가 지정돼 있지 않으면, compose는 `<프로젝트>-<서비스>` 이름의 이미지를 찾으므로 밖에서 빌드할 때 그 이름으로 태그해야 `--no-build`로 쓸 수 있다. (안 해 봄)
